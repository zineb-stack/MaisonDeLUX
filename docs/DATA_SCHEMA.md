# MaisonDeLUX — Data Schema V2

## Principles

Schema V2 preserves source evidence and parsed values together. A parser failure produces a null plus a status/reason; it never invents a value. Boolean amenities are nullable: `true` means explicitly present, `false` explicitly absent, and `null` not mentioned.

Availability classes:

- **A — reliable:** present consistently on current result cards or generated by collection.
- **B — occasional:** present only in some titles/details or page attributes; pilot measurement required.
- **C — unavailable:** not found in the current four-column historical export.
- **D — external:** requires another service/source, such as geocoding.

## Identity and collection

| Field | Type | Required | Null | Class | Description / example | Source and parsing |
|---|---|---:|---:|---|---|---|
| `listing_id` | string | yes | no | A/B | `mubawab.ma:native:98765` | Native site ID first, canonical URL hash second, content fingerprint last. Never a row number. |
| `listing_id_strategy` | enum | yes | no | A | `native_id`, `canonical_url`, `content_fingerprint` | Records how `listing_id` was built. |
| `source` | string | yes | no | A | `mubawab.ma` | Collector configuration. |
| `url` | string | pilot target | yes | B | Canonical public listing URL | Card anchor/detail page; UTM parameters and fragments removed. |
| `scraped_at` | ISO-8601 UTC | yes | no | A | `2026-08-14T12:00:00+00:00` | Collector clock. |
| `listing_date` | date/datetime | no | yes | B/C | Publication/update date | Only if explicitly exposed; never inferred from scrape time. |

## Transaction and price

| Field | Type | Required | Null | Class | Description / example | Source and parsing |
|---|---|---:|---:|---|---|---|
| `transaction_type` | enum | yes | no | A | `SALE`, `RENT`, `UNKNOWN` | Category/URL/title/details. Conflicts and absence become `UNKNOWN`; unknown is never silently sale. |
| `transaction_parse_reason` | string | yes | no | A | `explicit_sale_signal` | Auditable rule result. |
| `currency` | enum/string | no | yes | A | `MAD`, `EUR` | Explicit `DH`, `DHS`, `MAD`, `EUR`, `€`; no automatic conversion. |
| `raw_price_text` | string | yes | yes | A | `1 200 000 DH` | Exact normalized-whitespace source wording. |
| `price` | decimal | sale target | yes | A | `1200000` | Parsed amount in the original currency. Ambiguous/per-m²/request prices remain null. |
| `price_parse_status` | enum | yes | no | A | `PARSED`, `WARNING`, `MISSING`, `INVALID` | Parser outcome. |
| `price_parse_reason` | string | yes | no | A | `ok`, `price_on_request`, `currency_unknown` | Handles spaces/NBSP, commas, periods, million(s), `M`, `k`, MAD/DH/DHS/EUR, rent/month and price/m². |

## Location

| Field | Type | Required | Null | Class | Description / example | Source and parsing |
|---|---|---:|---:|---|---|---|
| `city` | string | pilot target | yes | A | `Casablanca` | Last comma component plus conservative aliases (`Casa`, `Tangier`, `Marrakesh`). |
| `quartier` | string | no | yes | A | `Maârif` | Preserved first component when separation is clear; never invented. |
| `address_text` | string | no | yes | A/B | Raw human-readable location | Same evidence as `location_raw`; may become richer from detail pages. |
| `latitude` | decimal | no | yes | D | `33.5731` | Only source-provided coordinates or an explicitly approved geocoder. |
| `longitude` | decimal | no | yes | D | `-7.5898` | Same rule as latitude. |
| `location_parse_status` | enum | yes | no | A | `PARSED`, `CITY_ONLY`, `AMBIGUOUS`, `MISSING` | Makes uncertain separation visible. |

## Property, surfaces and rooms

| Field | Type | Required | Null | Class | Description / example | Source and parsing |
|---|---|---:|---:|---|---|---|
| `property_type` | enum/string | pilot target | yes | A/B | `appartement`, `villa`, `duplex` | Title/details first, category/URL fallback; conflicting types are ambiguous. |
| `property_type_parse_status` | enum | yes | no | A | `PARSED`, `AMBIGUOUS`, `MISSING` | Type audit. |
| `surface_total_m2` | decimal | no | yes | A/B | `100` | Generic/surface totale/superficie evidence only. |
| `surface_built_m2` | decimal | no | yes | B | `250` | Explicit `habitable`, `construite`, `bâtie`, `built`. |
| `surface_land_m2` | decimal | no | yes | B | `500` | Explicit `terrain`, `parcelle`, `lot`. |
| `surface_parse_status` | enum | yes | no | A | `PARSED`, `WARNING`, `MISSING` | Multiple unlabeled surfaces become warning, not a guessed total. |
| `surface_parse_reason` | string | yes | no | A | `multiple_surface_types` | Explains ambiguity/missing evidence. |
| `rooms` | integer | no | yes | A/B | `4` | Explicit pièces. |
| `bedrooms` | integer | no | yes | A/B | `3` | Explicit chambres/`Ch.`. |
| `bathrooms` | integer | no | yes | A/B | `2` | Explicit salles de bain/`SDB`. |

## Building and condition

| Field | Type | Required | Null | Class | Description / example | Source and parsing |
|---|---|---:|---:|---|---|---|
| `floor` | integer | no | yes | B | `0` for RDC, `4` | Explicit floor wording only. |
| `total_floors` | integer | no | yes | B/C | `5` | Explicit building total only. |
| `construction_year` | integer | no | yes | B/C | `2019` | Explicit year only. |
| `condition` | enum | no | yes | B | `NEW`, `RENOVATED`, `TO_RENOVATE` | Deterministic text evidence. |
| `new_construction` | nullable boolean | no | yes | B | `true` | `neuf`, première main, en construction, etc. |
| `renovated` | nullable boolean | no | yes | B | `true` | `rénové`, refait à neuf. |

## Amenities, views and legal status

All fields below are nullable booleans extracted from explicit positive/negative wording. Current historical cards mention them inconsistently, so they are class **B**.

| Fields | Examples / evidence |
|---|---|
| `elevator`, `parking`, `garage` | ascenseur/lift, parking/place voiture, garage |
| `terrace`, `balcony`, `garden`, `pool` | terrasse/rooftop, balcon, jardin/RDC jardin, piscine |
| `furnished` | meublé/furnished versus explicitly non meublé/vendu vide |
| `security`, `concierge` | sécurisé/surveillance, concierge/gardien |
| `air_conditioning`, `heating`, `fireplace` | climatisation, chauffage, cheminée |
| `equipped_kitchen`, `double_glazing` | cuisine équipée, double vitrage |
| `sea_view`, `mountain_view` | vue mer/front de mer, vue montagne/Atlas |
| `title_deed` | titre foncier/individuel, melkia; missing text remains null |
| `proximity_text` | string such as `proche de la gare` | Explicit phrase kept as text; not converted to distance. |

## Validation and raw traceability

| Field | Type | Required | Null | Class | Description / example | Source and parsing |
|---|---|---:|---:|---|---|---|
| `validation_status` | enum | yes | no | A | `VALID`, `WARNING`, `INVALID` | Rule-based data audit, never model residuals. |
| `validation_reasons` | pipe-delimited string | yes | allowed empty | A | `unknown_transaction|missing_city` | All triggered reasons without deleting the record. |
| `title_raw` | string | yes | yes | A | Original listing title | Preserved before derived attributes. |
| `location_raw` | string | yes | yes | A | `Maârif, Casablanca` | Coexists with city/quartier. |
| `details_raw` | string | yes | yes | A | Original compact details | Coexists with surfaces/rooms/amenities. |

## Worked example from the historical CSV

Raw card:

```text
Titre: Appartement d’exception à vendre – Malabata Hills
Prix: 5 600 000 DH
Localisation: Malabata, Tanger
Details: 152 m² 7 Pièces 3 Chambres 2 Salles de bains
```

Selected V2 output: `transaction_type=SALE`, `price=5600000`, `currency=MAD`, `city=Tanger`, `quartier=Malabata`, `property_type=appartement`, `surface_total_m2=152`, `rooms=7`, `bedrooms=3`, `bathrooms=2`. Unmentioned amenities remain null; no pool, parking or view is invented.

## Storage

The proposed portable output is `data/raw/maisonlux_listings_v2.csv`, UTF-8 with BOM, fixed column order, empty CSV fields for nulls, and no index column. CSV remains appropriate for the PFE. Parquet may be derived later under `data/processed/` for typed analytics, but it does not replace raw CSV.
